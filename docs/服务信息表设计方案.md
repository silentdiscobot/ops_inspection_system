# 服务信息表 设计方案

> 适用范围：在现有"服务器管理"菜单下新增"服务信息"模块。
> 依据代码：`app.py`（1719 行）、`models.py`（809 行）、`templates/servers.html`、`static/app-shell.js`、`docs/系统说明文档.md`。
> 本文只描述方案，未改动任何代码。

---

## 1. 需求与目标

### 1.1 明确提出的字段

| 需求字段 | 处理方式 |
| --- | --- |
| 服务名称 | 主表字段，必填 |
| IP地址 | **不存副本**，外键指向 `servers.id`，IP 从服务器表取 |
| 归属系统（多个） | 字典表 + 多对多关联表 |
| 归属环境（多个） | 字典表 + 多对多关联表 |
| 部署目录 | 主表字段 |
| 启停命令 | 拆为 启动 / 停止 / 重启 三条命令 |
| 端口信息 | 主表字段，支持多端口描述文本 |
| 账号信息（多个） | 子表，密码 AES-GCM 加密，**查看需二次验证登录密码** |

### 1.2 设计目标

1. 与现有代码风格完全一致：Flask 装饰器路由 + 原生 `sqlite3` + Jinja2 模板 + ES5 脚本，不引入 ORM / 前端框架 / 新依赖。
2. IP 与服务器列表强一致：通过外键关联，不产生"服务器改 IP、服务信息还是旧 IP"的脏数据。
3. 账号密码**在数据库里加密、在接口里永不默认返回、在页面上二次验证后才显示**。
4. 每一次"看密码"都可追溯（审计日志）。

---

## 2. 关键设计决策

以下 6 项是方案的骨架，均给出推荐选项与理由。

### 决策 1：IP 用外键关联，不用文本冗余

`service_infos.server_id INTEGER NOT NULL REFERENCES servers(id)`。

- 列表/详情接口通过 `JOIN servers` 返回 `ip`、`server_name`、`os_type`，前端拿到的仍是"IP地址"这一个值，语义与需求一致。
- 新增/编辑表单里"IP地址"是一个**下拉选择框**（选项形如 `生产应用服务器01（10.0.0.11）`），而不是自由输入框，从入口上杜绝录错。
- 注意：`servers.ip` 在库里**没有唯一约束**（models.py:12-27），所以必须用 `server_id` 而不是 `ip` 做关联键，否则无法确定指向哪一条服务器记录。

### 决策 2：服务器删除时级联删除服务信息，并在删除前提示

`ON DELETE CASCADE`，与现有 `server_group_memberships` 的写法一致（models.py:32-34）。

- 服务器没了，挂在其上的服务信息没有存在意义，级联删除是合理语义。
- 但**静默删除是危险的**，所以配套：`/api/servers` 列表接口额外返回 `service_count`，前端删除确认文案改为
  「该服务器下还有 3 条服务信息，删除后一并移除。确定删除？」
- 备选方案是 `ON DELETE RESTRICT`（先解绑才能删服务器），摩擦更大，不推荐。

### 决策 3：归属系统 / 归属环境用字典表，不用 JSON 文本列

虽然 `inspection_tasks.proxy_rules` 用了 JSON 文本列（models.py:47），但本场景不适用：

- 需求是"可多个"，实际使用中必然出现"查一下订单系统在生产环境有哪些服务"——这是**按维度筛选**，JSON 列只能全表捞出来在 Python 里过滤。
- 现有代码已有完美先例可抄：`server_groups` + `server_group_memberships` + 左侧"分组管理"卡片 + `.tags-container` 多选药丸控件。

采用 4 张表：`service_systems`、`service_environments` 两张字典表，各配一张关联表。

> 可简化：如果嫌 4 张表多，可合并为 `service_dict_items(category, name)` + `service_dict_memberships(item_id)` 两张表，代价是分类只能靠应用层约束。**推荐按现有风格用 4 张明确的表**，代码可读性和外键完整性更好。

### 决策 4：启停命令拆成三条

需求写的是"启停命令"，推荐拆为 `start_command` / `stop_command` / `restart_command`：

- 单块自由文本在复制粘贴时容易连错行，运维现场最常要的是"重启"这一条。
- 未来若要做"一键重启"按钮，拆开才有结构化基础。
- 如果你更想要一个自由文本字段，直接只保留 `start_command` 并把标签改成"启停命令"即可，不影响其他设计。

### 决策 5：账号信息的暴露分三层

需求原文是"查看**账号信息**时需要目前登录的账号密码才可以查看"——注意门槛卡在"账号信息"整体，而不只是密码。因此：

| 层次 | 接口 | 返回内容 |
| --- | --- | --- |
| 列表 | `GET /api/services` | 只返回 `account_count`，**不含任何账号字段** |
| 详情 | `GET /api/services/<id>` | 只返回 `account_count`，**不含任何账号字段** |
| 账号明细 | `POST /api/services/<id>/accounts/reveal` | 二次验证通过后返回 用途 / 账号 / 类型 / **明文密码** / 备注 |

这样账号名也不会随列表接口流出（账号名本身对爆破有价值）。

### 决策 6：二次验证用"当前登录用户的登录密码"，每次都要验

- 复用现有 `get_user()` + `verify_password()`（app.py:109-117、app.py:338-346），不引入新机制。
- **不签发"验证通过凭证"**：每次点"查看账号信息"都要输一次密码。理由是实现最简单、无过期窗口可被利用。一次验证返回该服务**全部**账号，所以不存在"每个账号输一次"的体验问题。
- 前端明文只留在 DOM 文本节点里，**60 秒后自动清空**，关闭弹窗或离开页面立即清空；不写 `localStorage` / `sessionStorage` / URL。

## 3. 数据库设计

### 3.1 放置位置与迁移方式

- 新表 DDL 直接追加到 `models.py` 的 `SCHEMA_SQL` 字符串内（models.py:7-101）。
- `init_db()` 用 `cur.executescript(SCHEMA_SQL)`（models.py:114）执行，因为全部是 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，**老库重启后会自动建出新表，无需写迁移脚本**。
- 本次**不修改 `servers` 表**，所以不需要 `PRAGMA table_info` + `ALTER TABLE` 的守卫代码（models.py:115-131 那套只在给已有表加列时才需要）。
- 连接层已开启外键：`PRAGMA foreign_keys=ON`（models.py:107），因此级联删除真实生效，且支持 `servers → service_infos → service_accounts` 的链式级联。

### 3.2 表结构

```sql
-- 服务信息主表
CREATE TABLE IF NOT EXISTS service_infos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL DEFAULT '',                 -- 服务名称
    server_id INTEGER NOT NULL,                    -- 关联 servers.id，IP 由此得出
    service_type TEXT NOT NULL DEFAULT '应用服务',  -- 中间件/应用服务/数据库/定时任务/其他
    run_mode TEXT NOT NULL DEFAULT 'systemd',      -- systemd/docker/supervisor/脚本/k8s/其他
    version TEXT,                                  -- 版本号
    deploy_dir TEXT,                               -- 部署目录
    start_command TEXT,                            -- 启动命令
    stop_command TEXT,                             -- 停止命令
    restart_command TEXT,                          -- 重启命令
    ports TEXT,                                    -- 端口信息，如 8080/tcp(HTTP), 8443/tcp(HTTPS)
    config_path TEXT,                              -- 配置文件路径
    log_path TEXT,                                 -- 日志路径
    access_url TEXT,                               -- 访问地址
    owner TEXT,                                    -- 负责人
    status TEXT NOT NULL DEFAULT '运行中',          -- 运行中/已停止/已下线
    auto_start INTEGER NOT NULL DEFAULT 0,         -- 是否开机自启
    notes TEXT,
    created_by TEXT,                               -- 录入人（session['username']）
    created_at TEXT NOT NULL,
    updated_at TEXT,
    FOREIGN KEY(server_id) REFERENCES servers(id) ON DELETE CASCADE,
    UNIQUE(server_id, name)                        -- 同机不允许重名服务
);
CREATE INDEX IF NOT EXISTS idx_service_infos_server_id ON service_infos(server_id);
CREATE INDEX IF NOT EXISTS idx_service_infos_status ON service_infos(status);

-- 归属系统字典 + 关联
CREATE TABLE IF NOT EXISTS service_systems (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL
);
CREATE TABLE IF NOT EXISTS service_system_memberships (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    service_id INTEGER NOT NULL,
    system_id INTEGER NOT NULL,
    FOREIGN KEY(service_id) REFERENCES service_infos(id) ON DELETE CASCADE,
    FOREIGN KEY(system_id) REFERENCES service_systems(id) ON DELETE CASCADE,
    UNIQUE(service_id, system_id)
);

-- 归属环境字典 + 关联
CREATE TABLE IF NOT EXISTS service_environments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL
);
CREATE TABLE IF NOT EXISTS service_environment_memberships (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    service_id INTEGER NOT NULL,
    environment_id INTEGER NOT NULL,
    FOREIGN KEY(service_id) REFERENCES service_infos(id) ON DELETE CASCADE,
    FOREIGN KEY(environment_id) REFERENCES service_environments(id) ON DELETE CASCADE,
    UNIQUE(service_id, environment_id)
);

-- 账号信息子表（密码 AES-GCM 密文）
CREATE TABLE IF NOT EXISTS service_accounts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    service_id INTEGER NOT NULL,
    purpose TEXT,                                  -- 用途：应用账号/数据库账号/运维账号…
    username TEXT NOT NULL DEFAULT '',             -- 账号
    secret_type TEXT NOT NULL DEFAULT '密码',       -- 密码/密钥/免密/其他
    enc_password TEXT,                             -- AES-GCM 密文，非"密码"类型可为空
    remark TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT,
    FOREIGN KEY(service_id) REFERENCES service_infos(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_service_accounts_service_id ON service_accounts(service_id);

-- 审计日志（新增，见第 6 节）
CREATE TABLE IF NOT EXISTS audit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL,
    username TEXT NOT NULL DEFAULT '',
    client_ip TEXT,
    action TEXT NOT NULL,                          -- 如 service.reveal_account
    result TEXT,                                   -- ok / denied / failed
    target_type TEXT,
    target_id INTEGER,
    target_name TEXT,                              -- 冗余存名称，删除后仍可追溯
    detail TEXT
);
CREATE INDEX IF NOT EXISTS idx_audit_logs_created_at ON audit_logs(created_at);
CREATE INDEX IF NOT EXISTS idx_audit_logs_action ON audit_logs(action);
```

## 4. 后端接口设计

### 4.1 接口清单

沿用 `/api/servers`（app.py:732）的既有约定：列表返回**裸 JSON 数组**，写操作返回 `{"ok": true}` / `{"ok": false, "msg": "..."}`，删除用 `?id=` 查询串。

| 方法 | 路径 | 说明 | 角色 |
| --- | --- | --- | --- |
| GET | `/api/services` | 列表 + 筛选，裸数组 | admin, operator |
| GET | `/api/services/<int:id>` | 详情（不含账号明细） | admin, operator |
| POST | `/api/services` | 新增 | admin, operator |
| PUT | `/api/services` | 修改（id 在 body，与 `/api/servers` 一致） | admin, operator |
| DELETE | `/api/services?id=` | 删除 | admin, operator |
| POST | `/api/services/<int:id>/accounts/reveal` | 二次验证后返回账号明细 | 见 4.5 |
| GET/POST/DELETE | `/api/service_systems` | 归属系统字典（1:1 照抄 `/api/groups`） | admin, operator |
| GET/POST/DELETE | `/api/service_environments` | 归属环境字典（同上） | admin, operator |
| GET | `/api/audit_logs?limit=200` | 审计日志（阶段三页面用） | admin |

页面路由（全部 `@no_cache` + `@login_required` + `@role_required(['admin','operator'])`）：

| 路径 | 模板 | 说明 |
| --- | --- | --- |
| `/services` | `services.html`，`page_mode="list"` | 列表 |
| `/services-new` | `services.html`，`page_mode="new"` | 新增 |
| `/services/<int:id>/edit` | `services.html`，`page_mode="edit"` | 编辑 |

> **编辑页用独立页面而不是弹窗**。现有服务器编辑是 760px 弹窗（`servers.html:246-272`），但服务信息表单含多行账号子表，弹窗会挤到无法使用。独立页面同时省掉了 `openEditServer()` 那种"先拉全量列表再 find 一条"的取巧写法（servers.html:493-498）。

### 4.2 列表筛选参数

`GET /api/services?keyword=&server_id=&system_id=&environment_id=&service_type=&status=`

- `keyword` 在 Python 侧做后置过滤，沿用 `filter_servers_by_keyword`（app.py:545）的写法，搜索范围：服务名称、IP、服务器名称、部署目录、端口、负责人、系统名、环境名。
- 其余参数走 SQL 条件，`system_id` / `environment_id` 用 `JOIN ... memberships ON ... AND system_id = ?`（因为有 `UNIQUE(service_id, system_id)`，不会产生重复行）。
- 排序建议 `ORDER BY s.ip, si.name`。

### 4.3 校验函数

新增两个函数，仿 `validate_server_payload`（app.py:628-684）的写法，抛 `ValueError` + 中文文案。

#### （1）新增 `is_safe_tech_text`——这是必须解决的一个冲突

现有 `is_safe_display_text`（app.py:129-130）会拒绝 `< > &` 和 `\x00-\x1f`：

```python
return len(value or '') <= max_length and not re.search(r'[<>&\x00-\x1f]', value or '')
```

而运维的启停命令几乎必然包含这些字符——`cd /opt/app && ./start.sh`、`nohup java -jar app.jar > out.log 2>&1 &`。**直接复用该函数会导致命令字段永远提交失败**。因此为"技术类文本"单独放行：

```python
def is_safe_tech_text(value, max_length=200):
    """路径/命令/端口等技术文本：允许 shell 元字符，仅拒绝控制字符。
    安全性由"渲染时转义 + 后端永不执行这些字符串"保证，不靠输入过滤。"""
    return len(value or '') <= max_length and not re.search(r'[\x00-\x08\x0b\x0c\x0e-\x1f]', value or '')
```

允许：`& | ; $ ( ) " ' \` < >` 与换行（`\n`）、制表符（`\t`）；拒绝：NUL、退格、CR 等控制字符。

> **必须同时遵守两条约束，否则这个放行会成为漏洞来源：**
> 1. 前端渲染这些字段时一律转义（见第 7.5 节）。当前 CSP 允许 `'unsafe-inline'`（app.py:255-259），页面用 `innerHTML` 拼串，未转义即等于存储型 XSS。
> 2. 后端**绝不执行** `start_command` / `stop_command` / `restart_command`。它们只是被记录和展示的文本。将来若要做"一键重启"，必须复用 `inspection.py` 里 `test_proxy` 那套 curl 白名单校验思路（禁止分号、管道、命令替换等），绝不能直接 `run_cmd(ssh, start_command)`。

#### （2）新增 `validate_service_payload(data, require_credentials=True)`

| 字段 | 校验规则 |
| --- | --- |
| `name` | 必填；`is_safe_display_text(name, 100)` |
| `server_id` | 必填整数；`get_server()` 必须能查到，否则"所选服务器不存在" |
| `service_type` | ∈ {中间件, 应用服务, 数据库, 定时任务, 其他} |
| `run_mode` | ∈ {systemd, docker, supervisor, 脚本, k8s, 其他} |
| `version` | `is_safe_display_text(version, 50)` |
| `deploy_dir` / `config_path` / `log_path` | `is_safe_tech_text(x, 200)` |
| `start_command` / `stop_command` / `restart_command` | `is_safe_tech_text(x, 500)` |
| `ports` | `is_safe_tech_text(ports, 200)`；格式做宽松校验（逗号分隔、每段以数字端口开口），不追求严格正则，避免误伤真实运维写法 |
| `access_url` | 非空时必须以 `http://` 或 `https://` 开头，`is_safe_tech_text(200)` |
| `owner` | `is_safe_display_text(owner, 50)` |
| `status` | ∈ {运行中, 已停止, 已下线} |
| `auto_start` | 归一化为 0 / 1 |
| `notes` | `is_safe_display_text(notes, 500)` |
| `system_ids` / `environment_ids` | 整数列表；逐个验证字典项存在；去重 |
| `accounts` | 列表，长度上限 20；每条见下 |

账号行校验（每一条）：

| 字段 | 规则 |
| --- | --- |
| `purpose` | `is_safe_display_text(purpose, 50)` |
| `username` | 必填；`re.fullmatch(r'[A-Za-z0-9_.@\\$-]{1,64}', username)` |
| `secret_type` | ∈ {密码, 密钥, 免密, 其他} |
| `password` | 长度 ≤ 1024；`secret_type == '密码'` 且该行是新增或无已存密文时必填 |
| `remark` | `is_safe_display_text(remark, 200)` |

`username` 的正则比 `servers.username`（`[A-Za-z0-9_.-]{1,64}`，app.py:660）**故意放宽**，以容纳 `svc$`、`DOMAIN\user`、`svc@app.com` 这类真实服务账号。因为该字段只用于展示和复制、不进任何命令拼接，放宽是可接受的。

### 4.4 账号的"修改但保留原密码"契约（**最易出错的一处**）

需求决定了前端永远拿不到明文密码（除非走 reveal），所以编辑账号必须支持"留空 = 不修改"，这与现有服务器编辑的约定一致（`新密码（留空保持原值）`，servers.html:261 / app.py:787）。

`PUT /api/services` 请求体片段：

```json
"accounts": [
  {"id": 5, "purpose": "应用账号",   "username": "order_app", "secret_type": "密码", "password": "",       "remark": ""},
  {"id": 6, "purpose": "数据库账号", "username": "order_db",  "secret_type": "密码", "password": "N3wP@ss", "remark": ""},
  {"purpose": "运维账号", "username": "ops", "secret_type": "免密", "password": "", "remark": "sudo 免密"}
]
```

合并规则（在 `update_service` 的一个事务内）：

1. 取该服务现有账号 id 集合 `existing_ids`。
2. 带 `id` 的行 → `UPDATE`；`password` 为空则**保留原 `enc_password` 密文**，非空则重新 `aes_gcm_encrypt`。
3. 带 `id` 但不属于本服务的 → 返回 400「账号数据非法」（防止跨服务篡改）。
4. 不带 `id` 的行 → `INSERT`（新增）。
5. `existing_ids` 中有、但本次请求未出现的 id → `DELETE`。
6. 若某行 `secret_type == '密码'` 且既无新密码也无已存密文 → 400「账号 xxx 未填写密码」。

**⚠️ 必须区分"没传 `accounts` 键"和"传了空数组 `[]`"：**

- 请求体**不含** `accounts` 键 → 完全不动账号数据（`accounts_provided=False`）。
- 请求体**含** `accounts: []` → 清空该服务的全部账号（用户显式意图）。

原因：编辑页的账号区在未通过二次验证时是**锁定状态**（见 7.4），此时表单提交会没有账号数据。如果实现成"一律按请求体重建"，用户只是去改一个部署目录，就会把全部账号连同密码**静默删光**。同一个规则建议同样用在 `system_ids` / `environment_ids` 上（key 缺失 = 不变），比 `/api/servers` 里"始终 delete + 重插"的写法更安全。

### 4.5 查看账号信息接口（核心安全逻辑）

```
POST /api/services/<int:service_id>/accounts/reveal
装饰器：@no_cache @login_required @role_required(REVEAL_ROLES)
请求体：{"password": "<当前登录用户的登录密码>"}
```

处理流程：

1. **限流**：以 `(remote_addr, username)` 为键维护失败计数（照抄 `_login_failures` 的写法，app.py:48-51、137-158），15 分钟内失败 ≥ 5 次直接返回 429「验证失败次数过多，请15分钟后重试」。**独立计数，不与登录失败计数共用**，避免互相影响。
2. `username = session['username']`（app.py:380 的既有写法）→ `get_user(username)`；查不到返回 401。
3. `verify_password(user['password'], supplied)[0]` 为假 →
   记失败计数 + `record_audit(..., result='denied')` → 返回 403 `{"ok": false, "msg": "当前登录密码不正确"}`。
   **统一文案**，不区分"用户不存在 / 密码错误"。
4. 通过 → 清失败计数；查该服务全部账号，逐条 `aes_gcm_decrypt` →
   `record_audit(action='service.reveal_account', result='ok', detail='共 N 个账号')` →
   返回：

```json
{
  "ok": true,
  "expires_in": 60,
  "accounts": [
    {"id": 5, "purpose": "应用账号", "username": "order_app", "secret_type": "密码", "password": "******", "remark": ""},
    {"id": 6, "purpose": "运维账号", "username": "ops", "secret_type": "免密", "password": null, "remark": "sudo 免密"}
  ]
}
```

配套要求：

- **必须是 POST**，绝不能用 GET：GET 会被浏览器/代理缓存、进入历史记录，并可能被 `app-shell.js` 的预取逻辑（`static/app-shell.js:98-102` 会预取侧边栏所有链接）触发。
- 响应带 `Cache-Control: no-store`（`@no_cache` 已包含 `no-store`，app.py:191）。
- 单条账号解密失败（例如 AES 密钥轮换过，参见文档 14.5）时，该条返回 `"password": null, "error": "解密失败"`，整体仍返回 200，不要 500 掉整个请求。
- 日志与审计中**任何分支都不得写入明文密码**；异常信息里也不能带 `supplied`。
- 前端在请求发出后立即清空密码输入框的 value。

### 4.6 角色与权限

- 服务信息模块整体：`@role_required(['admin', 'operator'])`，与服务器管理一致；`viewer` 完全不可见（菜单也不渲染）。
- 看密码：默认 `admin` + `operator`。理由：操作员本来就能通过"测试连接/查看详情"用存储的服务器凭据登录服务器（app.py:686、845），看服务账号密码属于同类信任级别。
- 提供收紧开关：`config.py` 增加
  `SERVICE_REVEAL_ROLES = [r.strip() for r in os.environ.get("OPS_SERVICE_REVEAL_ROLES", "admin,operator").split(",") if r.strip()]`，
  安全要求高的环境设为 `OPS_SERVICE_REVEAL_ROLES=admin` 即可。

## 6. 审计日志（新增能力）

现状是**系统里完全没有操作日志**——没有表、没有助手函数、没有装饰器。而"谁在什么时候看了哪台服务的密码"恰恰是最需要留痕的动作，所以本次一并补上，成本很低（约 40 行）。

记录范围（阶段一）：

| action | 触发点 | detail 只写 |
| --- | --- | --- |
| `service.create` | 新增服务 | 空 |
| `service.update` | 修改服务 | 变更字段名列表，如 `部署目录, 账号(+1/-1/改2)` |
| `service.delete` | 删除服务 | 空 |
| `service.reveal_account` | 看密码 | `ok`：`共 2 个账号`；`denied`：空 |
| `service_dict.add` / `.delete` | 字典增删 | 字典名 |
| `server.delete` | 删除服务器 | `级联删除服务信息 N 条` |

**审计 detail 绝不写入字段值**：一是密码，二是启停命令——命令里常常内嵌密码（如 `mysql -pP@ssw0rd`），把命令原文抄进审计表等于二次泄露。只记"改了哪些字段"，不记"改成了什么"。

实现补充（落地时修正）：字段清单来自 `SERVICE_FIELD_LABELS`，但**归属系统 / 归属环境是多对多，不在该表里**，必须单独比较 id 集合后补记"归属系统""归属环境"，否则"只改了归属"的编辑会被记成"无字段变化"，审计就漏掉了真实变更。`test_update_audit_records_membership_changes` 守住这条。

## 13. 两个必须强调的前提

1. **生产环境必须启用 HTTPS**。看密码功能会把明文密码经网络送到浏览器；若系统仍以 HTTP 暴露，任何链路上的嗅探都能拿到密码。文档 §11 早有"建议前部署 HTTPS 反向代理"的表述，但对该功能而言这是**前置条件**而非建议。
2. **启停命令字段只存不执行**。为了让 `&&`、`2>&1` 这类真实命令能存进去，校验函数放行了 shell 元字符。安全边界因此转移到"渲染必转义"和"后端永不执行"两条上，未来任何"一键执行启停命令"的需求都必须先补命令白名单校验。
